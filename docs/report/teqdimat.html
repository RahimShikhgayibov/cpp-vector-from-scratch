Niyə new T[] yox?

OldVector (new T[]):
  reserve(3):   ctor #2, #3, #4   ← lazımsız
  push_back:    assign #2 ← #1
  pop_back:                       ← dağıdılmır
  ~vector:      dtor #4, #3, #2

mystl::vector (xam yaddaş):
  reserve(3):                     ← heç nə
  push_back:    copy #6 ← #5
  pop_back:     dtor #6           ← dərhal
  ~vector:      —
  • new T[n] yer ayıranda n obyekt qurur
  • 1. Default constructor-u olmayan tip kompilyasiya olunmur
  • 2. reserve lazımsız obyektlər qurur
  • 3. pop_back obyekti dağıda bilmir
  • Həll: yaddaşı və obyektləri ayırmaq

Mürəkkəblik və amortized O(1)

ƏməliyyatZaman
[], at, iterator-lar, sizeO(1)
push_back, emplace_backamortized O(1)
insert/erase (pos)O(n − pos)
copy, clear, ==O(n)
move, swapO(1)
reserve, shrink_to_fitO(n)

Aggregate metodu (2×):

T(n) = n + Σ 2j < n + 2n = 3n

→ əməliyyat başına < 3 = O(1)

Ümumi α: köçürmələr < α·n / (α − 1) → 2×: < 2n, 1.5×: < 3n
Sabit artım (+k) olsaydı: ~n²/2k = O(n²)

Trade-off-lar və nəticə

Trade-off-lar

  • assign həmişə yeni buffer ayırır → strong guarantee
  • Aralıq insert: std::rotate → sadə, alias-a qarşı təhlükəsiz
  • Iterator = pointer: debug yoxlaması yoxdur
  • Əhatə xaricində: allocator, vector<bool>

Nəticə

  • Tam std::vector interfeysi, 5 versiyalıq təkamül
  • Nəzəriyyə ölçmə ilə təsdiqləndi: köçürmələr < 2n
  • Big-O hər şeyi demir: cache 600×, noexcept 2×
  • std::vector ilə eyni sürət
